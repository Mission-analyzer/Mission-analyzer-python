# snake-sine-plane.lua

Скрипт для ArduPlane (Lua-скриптинг ArduPilot) — літак летить
синусоїдою (плавна хвиля ліворуч-праворуч), відхиляючись від прямого
курсу, потім повертається на курс і місія продовжується як звичайно.

Не для мультикоптерів — рухи побудовані під літак, що летить уперед з
постійною повітряною швидкістю, а не висить на місці.


## Вимоги

- ArduPlane зі зборкою, що підтримує Lua-скриптинг (позначка
  "with scripting" на [firmware.ardupilot.org](https://firmware.ardupilot.org)).
- Параметр `SCR_ENABLE = 1`, після зміни — перезавантаження плати.
- Відносно свіжа прошивка: `vehicle:set_target_location()` для Plane
  з'явилась не з першого дня скриптингу
  ([ArduPilot#13666](https://github.com/ArduPilot/ardupilot/issues/13666)).
  Якщо скрипт не рухає літак узагалі — перше, що варто перевірити.


## Встановлення

Файл `snake-sine-plane.lua` кладеться в папку `APM/scripts/` на
SD-карті польотного контролера. Два способи:

1. **Через MAVLink FTP** (без розбирання плати) — Mission Analyzer,
   Mission Planner чи будь-який інший GCS з підтримкою MAVFTP: зайти в
   менеджер файлів SD-карти, перейти в `APM/scripts/`, кнопка Upload.
2. **Фізично** — вийняти SD-карту, скопіювати файл у `APM/scripts/`
   звичайним провідником, вставити карту назад.

Якщо папки `APM/scripts/` ще немає — вона зʼявиться сама після
першого ввімкнення `SCR_ENABLE` і перезавантаження.


## Як вбудувати в місію

Мінімальна робоча місія:

| # | Команда | Навіщо |
|---|---|---|
| 0 | Home | стандартна перша точка |
| 1 | TAKEOFF | зліт |
| 2 | NAV_WAYPOINT | **напрямок польоту до цієї точки стає базовим курсом змійки** |
| 3 | NAV_SCRIPT_TIME | сам маневр, параметри — див. нижче |
| 4 | RETURN_TO_LAUNCH | (чи наступний звичайний пункт) |

Пункт 2 важливий — базовий курс змійки береться з фактичного напрямку
польоту в момент старту команди 3, тому попередній відрізок маршруту
має вести саме туди, куди потрібна змійка.


### Параметри NAV_SCRIPT_TIME (MAV_CMD 42702)

Одна й та сама команда MAVLink використовується ArduPilot для будь-якої
Lua-логіки в місії — сам протокол не розрізняє, який саме скрипт за
нею стоїть. `param1` ("command" у документації MAVLink) — довільне
число, яке інтерпретує вже конкретно ЦЕЙ скрипт:

| Параметр | Значення | Опис |
|---|---|---|
| param1 ("command") | `80` | старт змійки |
| param1 ("command") | `81` | аварійний запобіжник (див. нижче) |
| param2 ("timeout") | число > 0 | тривалість маневру, секунд |
| param3 ("arg1") | число | амплітуда бокового відхилення, метрів |
| param4 ("arg2") | число | період однієї повної хвилі, секунд |

Приклад — старт, таймаут 60с, амплітуда 40м, період хвилі 20с:

```
param1=80  param2=60  param3=40  param4=20
```


### Рядок у файлі .waypoints (формат QGC WPL 110)

Той самий формат, що читає Mission Analyzer. Той самий приклад
(старт, 60с, 40м, 20с) як рядок пункту №3:

```
3	0	3	42702	80	60	40	20	0	0	0	1
```

Колонки зліва направо: `index  current  frame  command  param1
param2  param3  param4  lat  lon  alt  autocontinue`. Поля
lat/lon/alt тут не мають сенсу для цієї команди (не позиційна) —
лишаються нулями.

Якщо `NAV_SCRIPT_TIME` ще немає в спадному списку діалогу "Додати
команду" в Mission Analyzer — рядок вище можна дописати в `.waypoints`
вручну, звичайним текстовим редактором, до завантаження файлу в
програму.


## Про команду 81

Задумана як аварійний запобіжник, **не** як гарантований спосіб
перервати вже виконувану команду 80 ззовні. `NAV_SCRIPT_TIME` в місії
виконується строго по черзі й чекає власного завершення (`timeout`
чи природне закінчення) — місія не переходить до наступного пункту, а
отже й не побачить команду 81, поки команда 80 сама не завершиться.
81 спрацьовує лише як захист на випадок повторного виклику скрипта зі
станом "ще виконується" з попереднього разу.


## Безпека

- Тестувати спершу на симуляторі (SITL) чи на висоті/території з
  запасом — маневр змінює траєкторію польоту в реальному часі.
- `timeout` (param2) — єдиний гарантований спосіб завершити маневр,
  якщо щось піде не так; не залишай його великим на перших тестах.
- Скрипт лише задає ціль через `vehicle:set_target_location()` —
  стандартний, документований механізм ArduPilot (той самий, що
  використовує офіційний приклад `copter-nav-script-time.lua`), не
  пряме керування рулями/оборотами двигуна.
